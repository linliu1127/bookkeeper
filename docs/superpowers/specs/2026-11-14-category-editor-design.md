# 類別編輯器（含子類別）設計

## 目的
使用者要自己新增／刪除類別，並在類別底下再分子類別（旅遊 › 機票／飯店；股票 › 各支股票），
記帳時可標註子類別。自訂內容要一起存進備份 JSON。

## 目標 / 非目標
- 目標：類別與子類別可增、刪、改名，記帳可選子類別、列表顯示子類別、備份含類別。
- 非目標：報表依子類別拆分（做法 A，報表仍只依大類彙總）；舊備份檔相容（使用者尚未實際使用）；類別操作不納入復原／重做。

## 做法（已選）
子類別只記在帳目上（`entry.sub`，選填字串），報表不動。另一種是報表可展開到子類別（B），本次不做。

## 設計
- **資料**：類別清單存在 `Store.kvSet('categories', {expense:[{name,icon,subs:[]}], income:[...]})`；
  第一次啟動以內建 `DEFAULT_CATS`（現有 CATS）當初始值。`CATS` 改為由這份清單衍生的唯讀視圖，
  `BK.CATS` 與 `iconOf` 介面維持不變，report.js 不用改。
- **帳目**：新增選填欄位 `sub`；沒有子類別就不寫。
- **刪除語意**：刪類別或子類別不動既有帳目（名稱仍留在帳目上）；只是不再出現在新增表單。
  編輯舊帳目時，若其類別／子類別已被刪，仍以額外選項顯示，避免存檔時被默默改掉。
  報表的類別來源改為「清單 ∪ 帳目實際用到的名稱」，已刪類別的歷史資料仍看得到。
- **備份**：格式升為 `{version:2, exportedAt, entries, categories}`。還原時類別以名稱聯集合併
  （子類別也聯集），並補上帳目用到但清單沒有的名稱。缺 `categories` 的檔案照常還原（內建預設）。
  類別有變動時呼叫 `Backup.bump()`／`schedule()`，與帳目一致。
- **UI**：漢堡選單新增「類別編輯器」→ 全螢幕頁（走 `openOverlay`）。頂部 支出｜收入 分頁；
  每個類別一列（圖示、名稱、子類別數、刪除鈕），點開展開子類別清單與「新增子類別」輸入；
  底部「新增類別」輸入名稱與 emoji（預設 🏷️）。名稱去前後空白、不可空白、同層不可重複（含大小寫不分的比對不做，單純全等）。
  刪除前 `confirm()` 說明「既有帳目不受影響」。
- **新增／編輯表單**：選好類別後，下方出現子類別一排 chip（可點選／再點取消，預設無）。
- **流水帳列表**：顯示「旅遊 › 機票」。
- **PWA**：新增檔案 `categories.js`（類別資料層、純邏輯、可 node 測試）與 `catedit.js`（編輯器 UI）；
  加進 `index.html`（載入順序在 app.js 前／後視依賴）、`sw.js` 的 `ASSETS`，`CACHE` 遞增。

- **改名**：類別與子類別皆可改名。同層新名稱與既有名稱重複（全等）就拒絕並提示，不合併。
  改名時同步批次替換 `entries`：類別改名換 `entry.category`（限同 type）；子類別改名只換
  「該 type、該類別」底下的 `entry.sub`。完成後 `Store.save()`、`Backup.bump()`／`schedule()`。
  改名不納入復原／重做。同名重建的類別會自然對回舊帳目（帳目以名稱記錄，無獨立 id）。

## 交給實作者決定
類別編輯器的版面細節、chip 樣式、輸入驗證訊息。

## 驗證
`categories.js` 以 node 測試：預設載入、增刪、重複與空白拒絕、合併還原、補齊帳目用到的名稱。
UI 在無頭 Firefox 嘗試截圖；無法實測的部分明確告知。
